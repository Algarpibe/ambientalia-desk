# F4-05 logging estructurado (Desk server) — Plan

> subagent-driven. Directo en `main`. Alcance: SOLO `apps/desk/server`. El motor (packages/zoho-sync) y el worker conservan `console.*` (fuera de alcance).

**Goal:** pino + pino-http en el server de Desk: niveles, request-id por request, salida legible en EasyPanel, sin loguear secretos (cookie/authorization redactados, sin bodies). Silencioso en tests.

## Task 1: logger + pino-http + reemplazo de console.* en el server
**Files:** `package.json` (deps), Create `apps/desk/server/util/logger.ts`, Modify `apps/desk/server/app.ts`, `apps/desk/server/index.ts`, `apps/desk/server/routes/*.ts` (donde haya console.*).

- [ ] **Step 1:** `npm i pino pino-http pino-pretty` (dependencies).
- [ ] **Step 2: `apps/desk/server/util/logger.ts`:**
```ts
import pino from 'pino'
const isTest = !!process.env.VITEST
export const logger = isTest
  ? pino({ level: 'silent' })
  : pino({
      level: process.env.LOG_LEVEL || 'info',
      redact: { paths: ['req.headers.cookie', 'req.headers.authorization'], remove: true },
      transport: { target: 'pino-pretty', options: { translateTime: 'SYS:standard', ignore: 'pid,hostname' } },
    })
```
- [ ] **Step 3: pino-http en `app.ts`** (en createApp, tras helmet/json/cookieParser, ANTES de las rutas):
```ts
import pinoHttp from 'pino-http'
import { randomUUID } from 'node:crypto'
import { logger } from './util/logger'
// ...
app.use(pinoHttp({ logger, genReqId: (req) => (req.headers['x-request-id'] as string) || randomUUID() }))
```
Esto añade `req.log` (child con reqId) y loguea cada request al completarse (método/ruta/status/ms/reqId). En el error-handler central: cambiar `console.error('Error no manejado:', err)` por `logger.error({ err }, 'Error no manejado')` (mantener el mapeo HttpError y el 500 genérico).
- [ ] **Step 4: Reemplazar `console.*` en `apps/desk/server`** por `logger`:
  - `index.ts`: `console.log('API en...')` → `logger.info(...)`; los `console.error(...)` de bootstrap/sync → `logger.error({ err }, '...')`; `console.log` de backfill/seed → `logger.info`.
  - `routes/tickets.ts`: los `void sync.X(id).catch((e)=>console.error(...))` (lazy+background) → `.catch((err)=>logger.warn({ err, ticketId: id }, 'sync bg falló'))`. Y el `console.error` del syncTicket/history lazy.
  - `routes/admin.ts`: `console.log/error` de backfill-archived → logger.
  - Cualquier otro `console.*` bajo `apps/desk/server`. (NO tocar packages/zoho-sync ni apps/hub-sync.)
  - Grep final: `grep -rn "console\." apps/desk/server --include=*.ts | grep -v test` → idealmente 0 (o justificar los que queden).
- [ ] **Step 5: Verificar:** `npm test` (verde; el logger es `silent` bajo VITEST → sin ruido). `npm run typecheck` (0). `npm run lint` (0 errores). `cd apps/desk && npx vite build` (OK — es server-side, no afecta el bundle front pero confirma que nada se rompió).
- [ ] **Step 6: Commit + push:** `git add -A` (solo lo del server + package.json/lock) → mejor `git add package.json package-lock.json apps/desk/server` → `git commit -m "feat(desk): logging estructurado pino + request-id en el server (F4-05)"` (trailer) → `git push origin main`.

## Watch out
- **Tests silenciosos:** el logger DEBE ser `silent` bajo `VITEST` (sin transport pino-pretty, que usa worker threads y ensuciaría/ralentizaría los tests). Verificar que `npm test` no escupe logs ni se cuelga.
- **No loguear secretos:** `redact` cubre cookie/authorization; pino-http por defecto NO loguea bodies — no añadir serializers que logueen `req.body`.
- **pino-pretty es dependency** (runtime, para EasyPanel legible), no devDependency.
- No tocar el motor ni el worker (conservan console.* → stdout).
- Si pino-http rompe algún test de supertest (no debería), investigar; no debe alterar status/bodies.

## Notas
- `LOG_LEVEL` env (default `info`) permite subir a `debug` en EasyPanel si hace falta.
- request-id: respeta `X-Request-Id` entrante o genera uno (UUID) → correlación de líneas por request.
